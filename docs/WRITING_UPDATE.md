# 질문·일기 작성 개선과 적용 안내

기준일: 2026-10-29. 이 문서는 최신 코드의 설계와 서버 적용 절차입니다.
과거 NCP HTTP 서비스의 성공과 새 모델·HTTPS의 적용 완료는 구분합니다. 최신 변경은 운영 서버에 자동 반영되지 않습니다.

## 1. 무엇이 바뀌었나요

사진 관찰은 HCX-005, 질문·작성·검토는 HCX-007 high 추론으로 구성했습니다.
질문은 사용자가 1~10개를 고르며 관점을 나누고 중복을 검사합니다.
초안은 원래 답변을 바탕으로 작성한 다음 원문과 대조하는 검토 요청을 한 번 더 보냅니다.
질문·답변 원문은 초안과 저장 기록에서 확인할 수 있습니다.
저장 전 초안은 명시적 재작성 버튼으로 교체할 수 있습니다.

```text
사진 → HCX-005 관찰 → HCX-007 질문 → 사용자 답변
                                      ↓
답변 전체 → WRITE → 답변 전체+초안 → REVIEW → 형식 검사 → 사용자 확인
```

## 2. 질문의 형태

이용자에게는 설명·마크다운 제목·질문 설계 이유 없이 짧고 자연스러운 질문 하나가 보여야 합니다.
`Q1` 같은 라벨이나 “이 질문은 기억을 떠올리도록 설계되었습니다” 같은 해설은 답변 입력을 방해합니다.
새 응답은 `{"question":"짧은 한국어 질문 하나?"}` JSON으로 요청합니다.
question-format.js가 120자 이내 단일 질문을 읽고 형식을 확인한 뒤 반복·관점을 검사합니다.
다중 질문·분석·너무 긴 응답·출력 잘림은 준비된 질문으로 대체합니다.
옛 기록은 확실한 Q1·Markdown 포장과 알려진 설계 설명만 표시용 복사본에서 정리합니다.
DB의 원래 질문·ID·답변은 유지하며 불명확한 옛 응답은 임의로 바꾸지 않습니다.
새 질문 형식의 정확한 자동 검사 결과는 [검증 기록](VERIFICATION.md)에 남깁니다.

질문은 앞선 답변의 구체적인 말과 연결하되 관계·사건·기분을 단정하지 않습니다.
사진 관찰이 틀리면 사용자 정정을 우선합니다. 원래 질문의 잘못된 전제를 일기의 사실로 가져오지 않습니다.

## 3. 일기 작성과 검토

사진·관찰문은 일기 작성 입력에서 제외합니다. 사실의 근거는 날짜·장소·답변입니다.
사용자 본인의 경험은 1인칭으로 쓰고 실제 다른 사람의 경험은 그 대상을 유지합니다.
답변 속 정정은 사실관계를 고치는 정보입니다. 정정 대화를 사진 촬영 현장의 대사로 옮기지 않게 지시합니다.
꾸며낸 분위기·교훈으로 분량을 늘리거나 구체적인 내용을 두세 문장으로 압축하지 않게 합니다.

예를 들어 “그 남성이 여권사진을 찍었나요?”라는 질문을 사용자가 “나고, 여권용이 아니라 일반 증명사진이야”라고 바로잡았다면, 일기는 정정한 시점·용도를 따라야 합니다.
이것은 의도한 동작을 설명한 예이며 실제 모델 출력 품질을 입증하는 사례가 아닙니다.

최대 두 번의 요청을 사용합니다. 첫 요청이 정상이어도 검토를 수행합니다.
첫 형식이 잘못되면 검토에는 candidate:null과 원래 답변을 보냅니다.
두 번째까지 형식·분량 검사를 통과하지 못하면 답변 원문으로 초안을 만듭니다.
인증·연결·HTTP 오류는 성공으로 숨기지 않고 실패를 안내합니다.

## 4. 무엇을 검사하나요

- JSON 객체가 완전한지 확인합니다.
- 제목과 문단 배열이 올바른지 확인합니다.
- 모든 answerId가 문단 전체에 정확히 한 번 연결되는지 확인합니다.
- 알려지지 않은 답변 ID와 중복 ID를 거절합니다.
- 본문 32,000자 상한과 현저한 축약을 검사합니다.
- 원래 답변과 의미 비교는 별도 AI 검토와 사용자 확인으로 보완합니다.

ID·분량 통과가 모든 사실 보존을 증명하지는 않습니다. 원문을 펼쳐 실제 결과를 읽어야 합니다.
매 문장을 복사하도록 강제하는 방식도 아닙니다. 같은 장면을 자연스럽게 합치되 세부 사항과 정정을 보존하는 것이 목표입니다.

## 5. 대기와 비용

질문은 최대 20,480 completion 토큰, 작성·검토는 각각 최대 32,768입니다.
텍스트 호출 한 번의 대기는 90초, 브라우저는 210초, Nginx 응답은 240초입니다.
토큰은 글자 수가 아니고 추론 사용량도 상한에 영향을 줍니다. 매번 최대량을 쓴다는 뜻은 아닙니다.
호출 수·추론 수준 증가로 응답 시간과 비용이 늘 수 있습니다.

## 6. 실제 서버에 적용

공개 저장소를 푸시하는 것만으로 서버가 바뀌지 않습니다. [자동 실행 업데이트](ALWAYS_ON_NCP.md)의 절차로 새 코드를 전송합니다.
DB와 사진 버킷은 새로 만들지 않고 기존 비밀 설정을 서버에서 유지합니다.
서버에서 실제 HCX-007 접근을 의도적으로 한 번 확인합니다.

```bash
cd /root/photo-memory-app
node --env-file=.env.local scripts/check-ncp-ai.mjs
npm run build
bash scripts/install-ncp-service.sh 203.0.113.10
```

IP는 본인 것으로 바꿉니다. 연결 점검은 실제 유료 API 요청일 수 있습니다. 키 자체를 출력하지 않습니다.
짧은 점검 요청은 추론을 끄며 앱의 질문·작성·검토는 high입니다.
AI_AUTH_FAILED이면 해당 모델 이용 권한·키를 확인합니다. 다른 모델로 몰래 전환하지 않습니다.

## 7. 적용 후 실제 확인

1. 기존 주소·브라우저에서 새로고침하고 쿠키를 유지합니다.
2. 앱 정보의 aiModels를 봅니다. 이는 설정 확인이며 실제 호출 성공과 다릅니다.
3. 새로운 질문이 짧고 설명 없이 나오는지 확인합니다.
4. 여러 답변으로 반복 질문이 생기는지 봅니다.
5. 저장 전 초안이라면 편집 글을 보관하고 명시적 재작성을 실행합니다.
6. 원래 질문·답변과 제목·본문의 사실·주어·세부 사항을 비교합니다.
7. 최종 저장과 재조회를 확인합니다.

저장한 본문을 새 코드가 자동으로 덮어쓰지 않습니다. 저장 완료한 글은 직접 수정합니다.
관련 파일은 clova-models.js, ai.js, writing-prompts.js, draft-format.js, question-plan.js, question-format.js, ConversationHistory.js입니다.
