# 발표·설명 준비 안내

이 문서는 개인의 이름·소속·역할·연락처 없이 발표 준비 방법을 설명합니다. 개인 명단과 계정 화면은 공개 저장소 밖에서 관리하고 제출 형식과 일정은 해당 수업의 최신 공지를 확인합니다.
발표에서는 설계한 내용과 실제 확인한 결과를 구분합니다.

## 1. 설명할 네 가지

| 항목 | 설명할 내용 | 보여 줄 증거 |
|---|---|---|
| 목적 | 사진에 없는 기억을 질문으로 꺼내기 | 가상 사용자 흐름 |
| 네트워크·서버 | NCP·VPC·앱·Private DB·저장소 | 민감값을 가린 실제 콘솔 |
| 역할·기여 | 실제 변경·검증·사용성 확인 | 파일·검사·재현 기록 |
| 실행 결과 | 사진→질문→답변→글→재조회 | 공개 가능한 테스트 데이터 |

API를 설명할 때는 브라우저의 요청을 앱 서버가 받아 DB에 접근하는 경로를 보여 줍니다. Postman은 이 요청을 시험하는 도구로, 사용자 서비스의 중간 서버에 해당하지 않습니다.
서명 URL로 비공개 사진을 잠시 읽을 수 있게 하면서 버킷 자체는 비공개로 유지합니다.

## 2. 20분 설명의 예

1. 목적과 가상 사용 사례: 3분.
2. 시스템·VPC·ACG·데이터 저장: 6분.
3. 답변 버튼의 실제 요청과 파일 경로: 4분.
4. 앱 시연과 원문·초안 비교: 5분.
5. 검증 범위·한계·다음 작업: 2분.

발표자료가 필요하면 공개 코드와 검증 결과를 보고 새로 만듭니다. 개인 명단·과거 캡처·발표 바이너리는 이 저장소에 포함하지 않았으므로 실제로 제공할 파일과 스크린샷만 링크합니다.

## 3. 역할과 기여 기록

화면·API 검증·클라우드 통합·사용성 테스트처럼 작업을 나눌 수 있습니다. 역할 배정표에 적은 일과 완료한 일을 구분하고 각자 실제로 수정한 파일과 확인한 결과를 설명합니다.
초보자는 안내 문구 수정, Network 요청 관찰, Postman 정상·오류 비교, 처음부터 완주 테스트로 참여할 수 있습니다.

## 4. 시연 전 확인

- 같은 주소·브라우저·쿠키로 접근합니다.
- 개인 사진 대신 테스트 이미지를 사용합니다.
- 질문·원답변·초안을 비교합니다.
- 저장 후 새로고침과 재조회를 확인합니다.
- ncloud·demo를 명확히 구분합니다.
- API 키·암호·쿠키·실제 DB 호스트·서버 주소를 가립니다.
- 실제 적용되지 않은 HTTPS·모델 변경을 완료로 설명하지 않습니다.

최근 자동 검사와 과거 NCP 확인 범위는 [검증 기록](VERIFICATION.md)에 있습니다.
질문을 받으면 성공 결과와 함께 익명 쿠키·복구·분산 처리·AI 정확성에서 아직 해결하지 못한 부분도 설명합니다.
