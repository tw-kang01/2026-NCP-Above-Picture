## 발견한 표현과 수정 예

긴 튜토리얼 곳곳에 짧은 설명이 따로 끊겨 있거나, 같은 뜻을 정의·대비 문장으로 다시 설명하는 구간이 있었습니다. 관련 문장을 연결하고 동작의 주체와 순서를 드러냈습니다.

| 위치 | 수정 전 | 수정 후 |
|---|---|---|
| README 도입 | 실행 명령만 복사하는 데서 끝나지 않도록… | 실행 명령과 함께 어느 컴퓨터에서 무엇이 실행되는지, 어떤 파일이 그 일을 맡는지 설명합니다. |
| README 8-1 | 컴퓨터 이름이 아니라 해당 통신에서의 역할을 가리킵니다. | 같은 컴퓨터도 누구와 통신하느냐에 따라 역할이 달라집니다. |
| 자동 실행 안내 | …배치를 수행합니다. | 앱과 런타임을 각각 어디에 배치하는지 동작으로 설명했습니다. |
| NCP 설치 안내 | 정상 결과는 …나오는 것입니다. | 버전 숫자가 나오면 정상입니다. |
| README 18-2 | 저장소에 개인정보가 없다는 것과 운영 앱이 개인정보를 처리하지 않는다는 것은 다릅니다. | 공개 저장소에는 개인정보를 제외했지만 운영 앱은 사용자의 사진·답변을 저장하고 AI 처리에 사용합니다. |

문장을 연결하면서 새로 붙인 불필요한 쉼표도 다시 점검했습니다. 실제 인용과 코드 안의 기호는 보존했습니다.

## 보존 확인

- 기존 문서 11개의 코드 블록·인라인 코드·Markdown 링크를 수정 전후로 비교했습니다.
- 명령어·API 경로·모델명·설정값·날짜와 수치값을 유지했습니다. 같은 설명을 합친 곳에서는 수치의 반복 횟수만 줄었습니다.
- 기술 표와 설치 순서를 유지하고 실제 검증과 미검증 상태를 구분한 문구도 남겼습니다.
- 독립 검토 중 토큰 상한을 실사용량처럼 단정한 문장과 `ncloud` 저장 조건이 빠진 문장을 발견해 바로잡았습니다.
- 프로그램 코드와 API 계약은 변경하지 않았습니다. 문서 링크·공개 파일 검사와 변경 형식 검사를 수행하며, 앱의 빌드·실행 검사를 새로 수행한 것으로 기록하지 않습니다.

이 기록은 문장의 표현과 구조를 검토한 결과입니다. 문체만으로 작성 주체를 판정하거나 AI 작성 확률·등급을 제시하지 않습니다.
