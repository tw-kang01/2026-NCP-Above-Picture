## 발견한 표현과 수정 예

긴 튜토리얼 곳곳에 짧은 설명이 따로 끊겨 있거나, 같은 뜻을 정의·대비 문장으로 다시 설명하는 구간이 있었습니다. 관련 문장을 연결하고 동작의 주체와 순서를 드러냈습니다.

| 위치 | 수정 전 | 수정 후 |
|---|---|---|
| README 도입 | 실행 명령만 복사하는 데서 끝나지 않도록… | 실행 명령과 함께 어느 컴퓨터에서 무엇이 실행되는지, 어떤 파일이 그 일을 맡는지 설명합니다. |
| README 8-1 | 컴퓨터 이름이 아니라 해당 통신에서의 역할을 가리킵니다. | 같은 컴퓨터도 누구와 통신하느냐에 따라 역할이 달라집니다. |
| 자동 실행 안내 | …배치를 수행합니다. | 앱과 런타임을 각각 어디에 배치하는지 동작으로 설명했습니다. |
| NCP 설치 안내 | 정상 결과는 …나오는 것입니다. | 버전 숫자가 나오면 정상입니다. |

문장을 연결하면서 새로 붙인 불필요한 쉼표도 다시 점검했습니다. 실제 인용과 코드 안의 기호는 보존했습니다.

## 2026-10-30: 실제로 따라가는 순서로 설명서 개편

앞의 검토는 문장 표현을 다듬은 기록입니다. 이후 사용자가 README가 맥락 없이 나열되어 따라가기 어렵다고 지적해 문서의 구성도 다시 검토했습니다. 앱 체험 뒤 문법·네트워크 정의·파일 목록으로 주제가 자주 바뀌고, NCP 준비 목록에서 실제 설치 폴더로 넘어가는 과정이 충분히 이어지지 않았습니다.

메인 README는 PC 도구 준비 → 코드 내려받기 → 앱 켜기 → 테스트 기록 저장 → NCP 자원 준비 → 처음 배포 → 기존 서버 업데이트 순서로 다시 썼습니다. 각 명령에는 실행할 창과 앞에서 준비할 값, 정상 결과와 실패했을 때 확인할 대상을 연결했습니다. 최초 설치와 업데이트는 별도 장으로 나누고 업데이트에서는 운영 `.env.local` 보존을 먼저 설명합니다.

코드를 따라가는 설명을 하나의 README에 몰지 말라는 요청에 따라 [코드 학습 안내](code/README.md), [화면과 요청](code/01-browser-and-request.md), [서버와 저장](code/02-server-and-storage.md), [사진과 AI](code/03-photos-and-ai.md)로 나눴습니다. [수정 연습과 파일 안내](CODE_MAP.md), [Postman 실습](POSTMAN_WALKTHROUGH.md)도 독립된 문서로 연결했습니다. 용어는 관련 실습에서 처음 필요해질 때 설명하고 파일·API 표는 다시 찾는 용도로 남겼습니다.

기존 수치·모델명·API 계약과 구현·모의 검사·실서버 검증의 구분을 실제 소스와 대조했습니다. 코드·환경 설정 값·운영 데이터는 변경하지 않았습니다. 새 문서의 상대 링크와 제목 연결, JSON 예시, PowerShell·Bash 명령 구문을 검사했고 Git에 올릴 파일도 공개 전 검사를 수행했습니다. 이 문서 작업에서 실제 서버 배포나 유료 AI 호출을 실행한 것으로 기록하지 않습니다.

긴 설명서를 작업 순서에 맞춰 쓰는 일반 원칙은 로컬 Codex 사용자 전역 지침과 공통 글쓰기 스킬에도 추가했습니다. 설치 안내와 코드 해설을 나누는 문서 배치는 이 프로젝트의 작성 기준에 남겼습니다.

같은 날 개편 문서를 다시 검토하면서 파일 안내에 있던 'build도 3000번 포트를 사용한다'는 설명을 바로잡았습니다. `build`는 실행 결과를 만들고 `dev`·`start`가 서버를 실행합니다. 첫 수정 실습도 실제 `MemoryApp.js`의 장소 입력 예시를 지정해 검색할 글과 바꿀 범위, 브라우저에서 확인할 위치가 이어지게 보완했습니다.

배포 설명에서는 `#`를 포함한 비밀번호가 따옴표 없이 입력되면 잘릴 수 있어 README·설정 예제·NCP 설정 문서에 따옴표 규칙을 추가했습니다. 문자 `$`의 Next.js 변수 확장과 Node 직접 점검의 해석 차이도 구분했습니다. 실제 비밀 설정을 읽지 않고 가상의 일반 변수만 메모리에서 비교해 확인했으며 앱 소스나 실제 클라우드 설정은 변경하지 않았습니다.
