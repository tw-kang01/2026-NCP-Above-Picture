## 2. 자동 검사가 확인하는 것

오프라인·모의 검사는 입력·이미지 형식·안전한 오류·CLOVA 요청 필드와 응답 형식을 통제해서 확인합니다.
사진 서명 URL, 관찰과 글쓰기 입력 분리, 반복 질문, 작성·검토, 원문 대안 등의 계약을 확인합니다.
실제 모델이 좋은 한국어 문장을 쓰는지, 계정에서 모델에 접근할 수 있는지를 모의 응답으로 증명할 수는 없습니다.

HTTP 검사는 demo 모드의 로컬 서버를 별도 포트에서 켜고 무작위 데이터 경로를 사용합니다. 이 서버에 실제 요청을 보내 기록 생성·사진·질문 수·답변·초안·재작성·버전·다른 소유자 차단·삭제를 확인합니다.
정리할 때도 검사가 만든 기록만 지우고 운영 기록은 건드리지 않습니다.

## 3. 과거 개발 과정의 확인

2026-10-23에는 로컬 MVP의 빌드, 당시 15개 HTTP 검사와 브라우저 사용 흐름을 확인했습니다.
사진 선택→질문 답변→초안→수정 저장→재조회, PC·모바일 크기의 배치를 살폈습니다.
이는 당시 버전에서 확인한 결과입니다. 최신 모델 출력과 실제 휴대전화의 전체 흐름은 별도로 검증해야 합니다.

2026-10-28에는 설치·API·코드·NCP 설명과 발표 구조를 정리했습니다.
이때는 문서를 정리했으며 실제 NCP 실행을 확인한 것은 아닙니다.

2026-10-29의 이전 대화에서는 실제 NCP DB의 SELECT 1 성공, photo-memory·nginx active, 서버 내부 앱·프록시 HTTP 200, 공인 HTTP 응답을 확인했습니다.
당시 사진 업로드·질문과 초안의 품질 문제가 보고돼 수정을 진행했습니다. 위 결과로 최신 HCX-007 권한·작문 품질·IP 인증서 발급·갱신 완료까지 확인한 것은 아닙니다.

## 5. 다시 검사하는 명령

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:app
npm.cmd run check:publish
```

실제 모델 연결을 점검하려면 NCP에서 다음 명령을 별도로 실행합니다.

```bash
node --env-file=.env.local scripts/check-ncp-ai.mjs
```

이 요청은 실제 계정 사용량을 소비할 수 있습니다. 짧은 연결 확인이며 전체 사진·일기 품질 평가는 아닙니다.
공개 전 검사·패키징 결과와 최종 커밋은 현재 저장소의 최종 작업 결과를 기준으로 기록합니다.
