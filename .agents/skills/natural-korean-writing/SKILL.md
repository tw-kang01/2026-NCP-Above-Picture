# 한국어 문체 검수

독자가 이해하고 행동할 수 있는 문장을 쓴다. 요청한 분량과 설명 수준을 유지하며 발견한 문제 구간만 고친다.

- 명령·코드·경로·API·수치·날짜·인용·출처는 보존한다. 필수 조건·선택 사항·추측·미검증 상태의 의미도 바꾸지 않는다.
- 번역투, 이중 피동, 추상 명사 나열을 실제 행위자가 하는 동작으로 풀어 쓴다.
- 상투적인 도입·의의 강조·결산, 반복되는 부정 대비, 같은 경고의 중복을 검토한다. 문맥상 필요한 설명은 남긴다.
- 한 문장씩 끊긴 설명은 관계가 이어지도록 묶고, 긴 문장은 독자가 구분해야 할 내용에 맞춰 나눈다. 종결어미를 억지로 바꾸지 않는다.
- 연결어미 뒤에 쉼표를 습관적으로 추가하지 않는다. 인용·코드·의미 구분에 필요한 쉼표는 보존한다.
- 표·목록·굵게 표시·괄호·대시는 비교와 순서 등 실제 기능이 있을 때 쓴다. 기술 문서의 API 표와 단계 목록을 무조건 산문으로 바꾸지 않는다.
- 원문에 없는 경험·감정·수사·근거를 추가하지 않는다. 격식 수준을 유지하고 흔한 한국어 표현을 일괄 금지하지 않는다.
- 수정 뒤 원문과 대조하여 기술적 의미와 조건을 확인한다. 문체를 AI 작성 여부의 증거로 단정하거나 검증하지 않은 판별 점수·등급을 제시하지 않는다.
- 하위 에이전트에게 문서 작업을 맡길 때 이 기준과 보존 대상을 전달하고 최종 결과도 검토한다.

프로젝트에 `docs/WRITING_STYLE.md`가 있으면 구체적인 문서 규칙도 읽는다. 없으면 위 기준으로 진행한다.
